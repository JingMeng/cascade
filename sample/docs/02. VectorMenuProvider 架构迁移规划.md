# VectorMenuProvider 架构迁移与实施记录

> 状态：已接入（Toolbar offset 扩展示例已完成，Kotlin 编译验证通过）
> 固化日期：2026-09-15  
> 范围：仅新增独立 Demo、资源和 Activity 声明；不修改现有 Sample 页面和既有 Cascade API；不使用 graphify。

## 1. 目标

在 Cascade 的 `sample` 模块中验证 Element Android 的基础菜单组织方式：

- Fragment 通过 `VectorMenuProvider` 声明菜单资源和菜单回调；
- 基类 Fragment 通过 AndroidX `MenuHost.addMenuProvider(...)` 注册菜单；
- 菜单生命周期绑定到 `viewLifecycleOwner` 的 `Lifecycle.State.RESUMED`；
- Activity 的 Toolbar 继续作为标准 Options Menu 宿主；
- Toolbar 的弹出菜单由 Cascade 的现有扩展替换为 `CascadePopupMenu`；
- 不引入与本次菜单验证无关的 State、Action、Effect、Model 或 ViewModel。

需要保留的基础协议只有四项职责：

```kotlin
interface VectorMenuProvider {
  @MenuRes
  fun getMenuRes(): Int

  fun handlePostCreateMenu(menu: Menu) {}

  fun handlePrepareMenu(menu: Menu) {}

  fun handleMenuItemSelected(item: MenuItem): Boolean
}
```

需要保留的基础注册流程是：

```kotlin
private fun setupMenu() {
  if (this !is VectorMenuProvider) return
  if (getMenuRes() == -1) return

  val menuHost: MenuHost = requireActivity()
  menuHost.addMenuProvider(
    object : MenuProvider {
      override fun onCreateMenu(menu: Menu, menuInflater: MenuInflater) {
        menuInflater.inflate(getMenuRes(), menu)
        handlePostCreateMenu(menu)
      }

      override fun onPrepareMenu(menu: Menu) {
        handlePrepareMenu(menu)
      }

      override fun onMenuItemSelected(menuItem: MenuItem): Boolean {
        return handleMenuItemSelected(menuItem)
      }
    },
    viewLifecycleOwner,
    Lifecycle.State.RESUMED
  )
}
```

### 2.2 当前 Cascade 能力

当前项目已有 `Toolbar.overrideAllPopupMenus(...)`：

- AndroidX/AppCompat 仍负责创建和维护 Toolbar 的 `MenuBuilder`；
- 扩展会接管 Toolbar overflow 和 action item 的 submenu 弹出；
- 现有 `MenuBuilder` 会直接交给 `CascadePopupMenu` 显示；
- 因此不需要自行实现 `CascadeMenuHost`，也不需要复制菜单树或手工转发每一个菜单回调。

这个结论比“自定义一个 Cascade MenuHost”更贴合项目现有 API，也更接近 Element 原始结构：标准 `MenuHost/MenuProvider` 处理生命周期，Cascade 只处理弹出层。

## 4. 调用链

```text
VectorMenuProviderSampleActivity
  -> setSupportActionBar(toolbar)
  -> toolbar.overrideAllPopupMenus(...)
  -> 添加 TimelineMenuDemoFragment

TimelineMenuDemoFragment.onViewCreated()
  -> VectorMenuBaseFragment.setupMenu()
  -> requireActivity() as MenuHost
  -> addMenuProvider(..., viewLifecycleOwner, RESUMED)

AndroidX 创建/准备 Toolbar 菜单
  -> onCreateMenu()
  -> inflate(getMenuRes())
  -> handlePostCreateMenu(menu)
  -> onPrepareMenu()
  -> handlePrepareMenu(menu)

用户点击 Toolbar overflow
  -> overrideAllPopupMenus 接管弹出
  -> CascadePopupMenu 使用 Toolbar 已有的 MenuBuilder
  -> 普通项或 submenu 叶子项被选择
  -> MenuProvider.onMenuItemSelected()
  -> VectorMenuProvider.handleMenuItemSelected()
```

## 5. Demo 覆盖点

- XML 菜单通过 `getMenuRes()` 提供；
- `handlePostCreateMenu()` 开启 group divider；
- `handlePrepareMenu()` 根据 Fragment 内的简单布尔值更新 Invite 的 enabled 状态和通知菜单标题；
- 页面按钮修改 Invite 状态并调用 `MenuHost.invalidateMenu()`；
- `handleMenuItemSelected()` 处理普通菜单项和 submenu 叶子项；
- Fragment 的两个布尔值通过 `onSaveInstanceState()` 保存，仅用于 Demo，不扩展业务模型层；
- Cascade popup 宽度单独配置为 `180dp`。

## 6. Manifest 决策

```xml

  android:name=".vectormenu.screen.VectorMenuProviderSampleActivity"
  android:exported="true"
```

该 Activity 不增加 `MAIN/LAUNCHER` intent-filter，原因是：

- 避免继续增加桌面 Launcher 入口，减少与已有两个入口的混淆；
- `exported=true` 允许使用 adb 显式启动 Demo；
- 不修改现有 `SampleActivity` 或 `ComposeSampleActivity`。

显式启动命令：

```powershell

```

## 8. 已知边界

1. `overrideAllPopupMenus` 的项目注释明确说明其 action submenu 接管依赖反射，稳定性不等同于公开 AndroidX API；本 Demo 复用现有实现，不隐藏这个边界。
2. Toolbar override 现在提供带 `show` 回调的重载，默认仍调用 `CascadePopupMenu.show()`；`VectorMenuProviderSampleActivity` 通过该重载调用 `showWithOffsets()`，把 top/end offset 注入 Toolbar 菜单，同时保持原有方法行为不变。
3. Demo 只验证菜单架构和回调链，不模拟 Element Timeline 的完整业务状态。
